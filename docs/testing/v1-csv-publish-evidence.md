## 二、场景 A：未齐备不能发布

### 操作步骤

1. 登录 `teacher01` → 「活动配置」。
2. 点「新建活动」，填名称「V1验收-未齐备发布」，其余保持默认 → 创建草稿。
3. 不导入名单、不添加题目，直接看「发布前检查」。

### 观察结果

检查清单五项中三项通过、两项未通过：

| 检查项 | 状态 | 说明 |
|---|---|---|
| 活动名称 | 通过 | V1验收-未齐备发布 |
| 开始与截止时间 | 通过 | 2026/10/23 18:46 → 2026/10/30 18:46 |
| 最大志愿数 | 通过 | 3 个 |
| 参与名单 | **未通过** | 名单为空，发布后没有学生能选择本活动 |
| 题目与名额 | **未通过** | 至少需要一个题目 |

页面提示：「还有 2 项未通过：参与名单、题目与名额。服务端会在发布时再校验一次。」

### 结论

- **页面层**：发布按钮为禁用（灰）状态。
- **服务端层**：绕过页面直接调 `POST /api/activities/:id/publish` 返回 `400 INVALID_INPUT`。

两侧都拒绝，符合「未齐备不能发布」。

## 三、场景 B：CSV 导入失败不破坏旧名单

### 操作步骤

1. 新建草稿「V1验收-CSV保护」。
2. 在「导入新名单」粘贴一份合法的 3 人 CSV → 点「预览名单」→ 点「确认替换」。
3. 再粘贴一份含错误的 CSV（姓名空、列数不足）→ 点「预览名单」。

### 第 2 步结果（成功路径）

- 提示「名单已整份替换：当前 3 人，配置版本升至 v1」。
- 「当前名单」显示 3 人：`20260001` 演示学生甲、`20260002` 演示学生乙、`20260003` 演示学生丙。
- 账号列正确区分：甲「已开通」，乙丙「未开通」。

### 第 3 步结果（失败路径）

红色错误横幅：`IMPORT_INVALID`「名单校验未通过，共 2 处问题；**已生效名单未被修改**」

逐行错误表：

| 行号 | 字段 | 原因 |
|---|---|---|
| 3 | `name` | 第 3 行：姓名不能为空 |
| 4 | `file` | 第 4 行：必须是 5 列（学号,姓名,入学年,专业,班级），当前 2 列 |

「确认替换」按钮保持禁用。

### 关键验证：旧名单未被破坏

失败之后：

- 页面「当前名单」仍显示 **3 人**，与失败前一致。
- 直接查接口 `GET /api/activities/:id/participants` 返回 `participants: 3`，学号仍为 `["20260001","20260002","20260003"]`。

### 结论

导入失败**没有**产生任何副作用，旧名单完整保留。

## 四、场景 C：五列格式校验覆盖

在场景 B 的第 3 步中同时验证了两种错误，此外在单元测试中覆盖了全部格式规则（`apps/api/src/routes/activities/config-roster.test.ts`，20 条）：

| 规则 | 错误码 | 用例 |
|---|---|---|
| 列数必须为 5 | `COLUMN_COUNT` | 通过 |
| 必填列不能为空 | `REQUIRED` | 通过 |
| 入学年必须 4 位数字 | `INVALID_FORMAT` | 通过 |
| 文件内学号不能重复 | `DUPLICATE` | 通过 |
| 与已有学生档案一致 | `PROFILE_MISMATCH` | 通过 |
| 空文件 / 只有表头 | `EMPTY` | 通过 |
| 行数上限 5000 | `TOO_MANY_ROWS` | 通过 |

支持格式：UTF-8 BOM、CRLF/CR/LF、双引号包裹、`""` 转义、单元格内逗号与换行。

## 五、验证中发现的缺陷

### BUG-M2-001：齐备性检查未通过时发布按钮仍可点击

| 项 | 内容 |
|---|---|
| 关联用例 | 场景 A |
| 等级 | **P2**（服务端已拦住，但页面误导教师） |
| 现象 | 检查清单显示 2 项未通过，但「发布活动」按钮仍是可用状态 |
| 原因 | `PublishPanel.tsx` 的 `disabled` 只判断草稿状态与 busy，未纳入 `blocking` |
| 影响 | 教师点下去会得到 400，但页面没有任何阻止，容易误以为已发布 |
| 修复 | PR #26，`blocking.length > 0` 时禁用并说明缺哪几项 |
| 状态 | 已修复，待合并 |

修复后复测：按钮 `disabled=true`；服务端行为不变（仍返回 400）。

> 说明：`unknown` 状态（如题目接口返回 501）不计入 `blocking`，避免环境未就绪时把教师卡死。此行为在修复后保留。
