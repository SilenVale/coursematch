# 选课助理 E2E 验收任务：从零到「可发布」成品

> 用途：用**固定输入**测助理能否走完「信息收集 → 确认创建 →（可选）发布」，并在工作台看到真实选课活动。  
> 环境：Dev [https://coursematch-dev.onrender.com](https://coursematch-dev.onrender.com) 或本地 `http://localhost:5173`  
> 账号：`teacher_blank` / 演示密码见 README。

---

## 1. 验收目标

| 级别 | 目标 | 通过标准 |
|------|------|----------|
| **P0（必过）** | 助理驱动**创建**一场选课 | 工作台出现新活动；生命周期 **DRAFT**；名称/截止/名单/一门课与下表一致 |
| **P1（推荐）** | 继续**发布** | 生命周期 **PUBLISHED**；学生端可见该活动（若已开通账号） |
| **P2（可选）** | 开通学生账号 | 名单内学号可登录（需再确认「开通账号」） |

本任务默认验收到 **P0**；有时间再做到 P1。

## 2. 规定输入（不要改字，便于对照）

### 2.1 活动与课程

| 字段 | 规定值 |
|------|--------|
| 活动名称 | `助理验收-2026秋选修` |
| 报名截止 | `2026-11-20 18:00`（北京时间） |
| 课程名称 | `数据结构与算法` |
| 授课教师 | `李老师` |
| 上课时间 | `周四 7-8 节` |
| 招生名额 | `30` |
| 志愿个数 | 不说即可（系统默认 **3**） |

### 2.2 名单

使用仓库文件（五列 CSV）：

`docs/testing/fixtures/assistant-roster-demo.csv`

共 **5 人**，学号 `20261001`～`20261005`。

## 3. 操作步骤（推荐：分步，便于看助理是否在「逐项记」）

登录 → 顶栏 **选课助理**。

**第 1 句（开场 + 名称 + 截止 + 课程）：**

```text
我要办一场选课。活动名称：助理验收-2026秋选修。报名截止 2026-11-20 18:00。一门课：数据结构与算法，李老师教，周四 7-8 节，名额 30。
```

**第 2 步：** 点输入栏 **「+」**，选择上面的 `assistant-roster-demo.csv` 导入（或粘贴 CSV 全文）。

**第 3 步：** 若助理仍追问缺项，按提示补一句；直到出现 **「确认创建」** 卡片（摘要里应含名称、时间、名单行数、课程信息）。

**第 4 步：** 点 **确认创建**（或发送「确认」）。

**第 5 步（P0 验收）：** 去 **工作台**，找到 **「助理验收-2026秋选修」**，点 **管理选课**，核对：

- 基本信息：名称、截止时间  
- 名单：5 人，学号与 CSV 一致  
- 课程：数据结构与李老师、周四 7-8 节、名额 30  
- 状态：**草稿 DRAFT**

**第 6 步（P1，可选）：** 回到助理，说「发布这场选课」→ 出现 **确认发布** → 确认 → 工作台状态变为 **已发布 PUBLISHED**。

**第 6b 步（可选，测改表）：** 创建成功后说：「再加刘老师教数据结构与算法，周四 7-8 节，名额 30，时间跟之前一样」→ 出现 **确认添加课程** → 确认 → 在 **开设课程** 里应看到 **李老师、刘老师** 两行。

## 4. 一键版（测「一句话能填多少」）

只发一段（不含 CSV，名单仍用 **+ 导入 CSV**）：

```text
创建选课：助理验收-2026秋选修，截止 2026-11-20 18:00。课程 数据结构与算法，李老师，周四 7-8 节，名额 30。名单我接下来导入 CSV。
```

导入 CSV 后，等 **确认创建** → 确认。

## 5. 失败判定与排查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 一直不出确认创建 | 缺截止/名单/课程某一项 | 看助理追问；补全后再试 |
| 确认后工作台没有 | 未登录教师 / 创建 API 失败 | 看页面红字；Dev 看 Render 日志 |
| 只有规则回复、很机械 | DeepSeek 未接入 | 应显示「DeepSeek 由站点提供」；否则仍可用规则模式完成 P0 |
| 刷新后对话没了 | 旧版未持久化 | 已支持本浏览器恢复；或按本任务重新走一遍 |
